## Series that would not play now play

Most of this release comes from one finding. Sampling a real provider — 40 series, 1,436 episodes — showed the catalogue is overwhelmingly Matroska:

| Container | Episodes |
|---|---:|
| `.mkv` | 1,201 |
| `.mp4` | 235 |

**84% of episodes were in a container no browser and no Android WebView can play.** Not a codec problem and not a network problem: the request succeeded, the bytes arrived, and the `<video>` element reported a bare format error. An `.mp4` episode played on exactly the path an `.mkv` one failed on.

Three changes follow from that:

- **The Android app plays Matroska itself.** A Media3/ExoPlayer activity handles the containers the WebView cannot, and reports position and completion back — so resume and watch history cover the whole catalogue, not just the playable minority.
- **Unplayable titles are marked before you tap them**, instead of spinning for twenty seconds and failing.
- **The player stops guessing.** It used to try `.mp4`, `.m4v` and `.mov` in turn. This provider answers a request for a container it does not hold with `200 OK`, `text/html` and an empty body — not a 404 — so every speculative attempt looked like a success and the diagnosis blamed the device. An unplayable container is now recognised before the first request: 5 ms instead of four attempts.

## The remote is served by the television

On the Android app the TV opens a port and serves the remote interface itself. The QR code encodes the TV's own LAN address, re-resolved each time it is shown so a network change cannot produce a code that scans and then times out.

Pairing needs no internet, and neither the catalogue nor the provider credentials leave the local network. When this path is available the public MQTT broker and the WebRTC handshake are not started at all — measured: zero WebSocket connections attempted. The relay remains only for the browser build, where no port can be opened.

## Security

- **Credentials no longer reach the public broker.** Stream URLs carry the Xtream username and password in their path; only the session header was being redacted, so the `channelUrl` in every state publish and the `url` on every catalogue item went out verbatim.
- **Pairing is enforced.** Rooms were `ROOM-` plus four digits — 10,000 possibilities against a public broker — and any offer naming the room was accepted. Rooms are now 18 random characters with a 24-character pairing secret that travels only in the URL the QR encodes.

## Playback fixes

- Browsing a season no longer changes what is playing. The series context was set by *browsing* and never cleared, so a film's position was filed under whichever episode you last looked at, finishing a film autoplayed an unrelated episode, and the resume seek fired on every `playing` event — dragging you back each time you tried to seek.
- A stream running below realtime was diagnosed as a decoder freeze and repeatedly nudged; it is now correctly a stutter, and the "four stutters, drop a rendition" escalation beneath it is reachable rather than dead code.
- Streams that were playing perfectly were charged a stall every 500 ms, which demoted the healthiest source available. Measured: 10 stalls before, 0 after, while genuine starvation still charges all 10.
- One press of P+ no longer skips two channels.
- Episodes without a still show a labelled placeholder instead of an empty box.

## Diagnostics

When a stream genuinely cannot play, the app says why — provider rejection, an unpublished episode, an undecodable container — rather than showing a spinner and then nothing. `quantumDiagnostics()` in the console prints a shareable report with credentials redacted.

### Installing

Sideload the attached APK, or use the **Downloader** app on Android TV / Fire TV:

```bash
adb install -r Quantum-IPTV-v2.2.0.apk
```

> **This APK is debug-signed.** No release keystore was configured when it was built. It installs and runs fine by sideload, which is how most Android TV boxes take it — but it cannot be published to Play and should not be treated as a distributable build. To produce one, build from source with `QUANTUM_KEYSTORE_FILE`, `QUANTUM_KEYSTORE_PASSWORD`, `QUANTUM_KEY_ALIAS` and `QUANTUM_KEY_PASSWORD` set; the build warns loudly when they are absent.

### Known limitations

- Matroska titles cannot play in a mobile **browser** — that is a browser limitation with no workaround. Use the Android app.
- The remote UI still loads its webfont from Google Fonts; it falls back to system fonts offline.
